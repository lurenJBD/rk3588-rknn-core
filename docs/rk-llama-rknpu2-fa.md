# rk-llama.cpp jina-embeddings-v5-small (Q8_0) Benchmark Result

Performance evaluation of the RKNPU2 hardware acceleration backend in `rk-llama.cpp` (`opi5-rknpu2-embed-opt` branch, commit `8cb318904`), executed on the reference platform.

- Upstream Project: <https://github.com/pty819/rk-llama.cpp/tree/opi5-rknpu2-embed-opt>
- Hardware & Platform: Orange Pi 5 Plus (Rockchip RK3588, 3 NPU cores, 6 TOPS INT8), mainline Linux 7.2.5. Full platform specifications are documented in [compatibility.md](compatibility.md).
- Runtime & Driver: `librknnrt.so` v2.3.2, DKMS `0.9.8-7`, mainline `rknpu` driver commit `842e9e93d721915fdbae63a1bd040f0f934096a8` (module srcversion `80D94120AADEE0271B5AFD8`).

> [!NOTE]
> Test environment: **2026-10-13**, Orange Pi 5 Plus, mainline Linux 7.2.5, DKMS **`0.9.8-7`**, driver commit **`842e9e93d721915fdbae63a1bd040f0f934096a8`**, module srcversion **`80D94120AADEE0271B5AFD8`**, `librknnrt.so` v2.3.2. CPU and NPU governors were set to `performance`; the NPU ran at 800 MHz.
>
> End-to-end values are medians of 3 process runs; each process run is the `llama-bench` average of 3 iterations (`-r 3`). Microbenchmark values are medians of 3 `fa-hardware-bench` runs. Run-to-run variance was material at short sequence lengths, so the medians should be treated as the representative values.

## 1. Workload & Model Architecture

The benchmark evaluates end-to-end embedding inference on the **`jina-embeddings-v5-small`** retrieval model (`v5-small-retrieval-Q8_0.gguf`), based on the **Qwen3-0.6B** decoder-only embedding architecture (`--pooling last`, `--embd-normalize 2`).

| Architectural Parameter | Value | Description |
|---|---|---|
| Model Architecture | Qwen3-0.6B | 28 Transformer layers, decoder-only embedding |
| Model Weight Format | Q8_0 GGUF (604.15 MiB) | 596.05M total parameters |
| Hidden Size / FFN Size | 1024 / 3072 | Hidden dimension and intermediate feed-forward size |
| Head Dimension ($D$) | 128 | Per-head key/query vector dimension |
| Query Heads ($H$) | 16 | Number of attention query heads |
| Key/Value Heads ($H_{kv}$) | 8 | Grouped-query attention (GQA ratio 2:1) |
| Attention Softmax Scale | 0.125 ($1/\sqrt{128}$) | Standard query-key scaling factor |
| KV Cache Type | F16 | Half-precision key/value cache |
| Acceleration API | `rknn_matmul_api` | Hardware INT8/FP16 native tensor matrix multiplication |
| Concurrency Dispatcher | `rknpu-fa` worker pool | Multi-threaded task dispatching across NPU hardware contexts |
| Cache Maintenance | `rknn_mem_sync` | Synchronous device-host memory synchronization |

### Evaluated Acceleration Configurations

- **NPU Flash Attention ON (`RKNPU_FA=1`)**: Attention projection and softmax-weighted value reduction are offloaded to NPU hardware via `rknn_matmul_api` and adaptive tile dispatch.
- **NPU Flash Attention OFF (`RKNPU_FA=0`)**: MatMul layers run on NPU, while Flash-Attention computation falls back to the host Cortex-A76 CPU NEON fp16 kernel.

## 2. Measured Benchmark Results

All benchmarks were executed pinned to the Cortex-A76 performance cluster (`taskset -c 4-7`, `llama-bench -t 4`) with CPU and NPU governors set to `performance` (NPU at 800 MHz). End-to-end results are medians of 3 process runs; each process run uses `llama-bench -r 3` (`-embd 1 -b 2048 -ub 2048`). Microbenchmark results are medians of 3 runs.

### 2.1 End-to-End Model Embedding Performance

| Prompt Tokens | NPU FA ON (tok/s) | NPU FA ON Latency (ms) | NPU FA OFF (tok/s) | NPU FA OFF Latency (ms) | Speedup | Status |
|---|---|---|---|---|---|---|
| 53 | 264.81 | 306.31 | 205.73 | 392.24 | 1.29x | PASS |
| 128 | 282.77 | 543.21 | 247.36 | 581.40 | 1.14x | PASS |
| 256 | 371.76 | 768.06 | 271.84 | 955.56 | 1.37x | PASS |
| 512 | **424.03** | **1272.99** | 281.10 | 1846.58 | **1.51x** | PASS |
| 1024 | 345.91 | 2978.14 | 225.18 | 4561.04 | 1.54x | PASS |
| 2048 | 279.31 | 7356.25 | 162.23 | 12635.43 | 1.72x | PASS |

Key observations:
- **NPU Flash-Attention acceleration**: NPU FA ON is faster than CPU FA at every measured length, with a **1.14x–1.72x** median speedup.
- **Long Sequence Acceleration**: At $N = 1024$ and $N = 2048$ tokens, NPU FA ON reaches **345.91** and **279.31** tok/s, reducing median latency from 4.56 s to 2.98 s and from 12.64 s to 7.36 s, respectively.
- **Peak Throughput**: Peak median embedding throughput reaches **424.03 tokens/second** at $N=512$.

### 2.2 Embedding Numerical Precision Verification

Embedding vector accuracy was verified across 1024-dimensional outputs generated by `llama-embedding` (`--pooling last`, `--embd-normalize 2`). The cosine check was repeated in each of the 3 process runs; all runs returned the same value:
- **Cosine Similarity**: `0.996608` (compared against CPU reference output; threshold $\ge 0.996$, **PASS**).
- **Output Validity**: Both FA ON and FA OFF outputs contained 1024 finite elements with zero `NaN` or `Inf`.

## 3. Independent Verification Evidence

Hardware execution was independently validated without relying exclusively on process exit codes:

1. **Device Enumeration**:
   `llama-bench --list-devices` reports active discovery of the Rockchip NPU hardware backend:
   ```text
   Available devices:
     RKNPU: Rockchip NPU (0 MiB, 0 MiB free)
   ```
2. **Hardware Interrupt Delta**:
   Hardware interrupt counters across `/proc/interrupts` confirmed balanced load and continuous execution across all three physical NPU cores during the real model benchmark:
   - IRQ 112 (`fdab0000.npu`, Core 0): +84,752 interrupts
   - IRQ 113 (`fdac0000.npu`, Core 1): +82,886 interrupts
   - IRQ 114 (`fdad0000.npu`, Core 2): +82,682 interrupts
   - Total hardware interrupts generated: 250,320 (representative run, run 2 of 3)
3. **Kernel Stability**:
   - Zero kernel oops, fault, or IOMMU page fault entries observed in `dmesg`.
   - Kernel taint status remained unchanged at `4096` (`TAINT_OOT_MODULE`).
